# 云合产品与新闻 Agent 设计

**日期：** 2026-07-16  
**状态：** 已确认，作为重构业务基线  
**范围：** 通用多 Agent 产品定位、云合调度、新闻、旅行、学术 Agent、来源库与审核流程

## 1. 产品定位

Yunhe 是通用多 Agent 平台。云合是调度员，不是又一个垂直领域专家；它识别用户意图，选择合适的子 Agent，传递必要上下文，汇总结果并在没有匹配 Agent 时提供通用回答。

第一批内置子 Agent：

| Agent | 职责 | 允许的专用能力 |
| --- | --- | --- |
| 云合 | 意图识别、调度、上下文传递、结果汇总、通用兜底 | 仅调度和通用对话能力；不替代垂直 Agent |
| 新闻 Agent | 热点解读、新闻搜索、交叉验证、深度研判 | 新闻检索、来源评估、证据编排 |
| 旅行 Agent | 行程规划、地图、出行、天气、预算 | 旅行领域工具与行程数据 |
| 学术 Agent | 论文搜索、引用分析、研究方向与学术写作 | arXiv、学术搜索与引用工具 |

情感识别不属于已确认的产品价值，列为删除范围。删除时同时移除其配置、模型调用、指标、测试、前端展示和调度依赖，不保留“空壳”开关。

## 2. 云合调度与会话模式

用户可以主动选择新闻、旅行或学术 Agent；未选择时，新会话默认由云合处理。云合在运行时接收所有可委派子 Agent 的 `name`、`description` 和能力摘要，不能依赖硬编码领域关键词来维护调度逻辑。

### 会话模式

| 模式 | 进入方式 | 每轮处理规则 | 退出方式 |
| --- | --- | --- | --- |
| 默认云合 | 用户未选择 Agent | 云合逐轮判断：简单通用问题直接回答；专业、实时或工具型问题最多委派一个子 Agent；该轮结束后控制权回到云合。 | 不适用。 |
| 手动锁定 | 用户主动选择子 Agent | 所有后续消息由所选 Agent 处理，不再自动重新路由。 | 用户切回云合或新建会话。 |
| 新闻研判锁定 | 用户点击新闻卡片的“AI 深度研判” | 所有后续消息强制由新闻 Agent 处理，并保持 `news_id` 锚点。 | 用户结束研判、返回云合或新建会话。 |

云合直接处理低风险、无需专用工具的任务，例如基础计算、常识问答、改写、翻译和简单写作。涉及新闻核验、旅行规划、学术检索，或需要实时信息和专用工具的请求，云合委派给匹配的子 Agent。

第一版只允许单轮委派一个 Agent。复合问题由云合选择主导 Agent 或要求用户澄清；不支持多 Agent 并行、串行工作流或结果自动融合。

前端需显示本轮实际处理者，但默认云合会话在委派完成后不得被永久切换到子 Agent。手动锁定和新闻研判锁定必须有明确的状态标识与退出操作。

## 3. 新闻首页与会话行为

新会话首页展示由后端热点池提供的新闻卡片或快捷问题。每张新闻卡片至少包含：

- `news_id`：稳定的内部标识。
- `title`：新闻标题。
- `source`：来源名称。
- `url`：原始新闻链接。
- `summary`：来源提供或合法取得的简短摘要。
- `published_at`：原始发布时间；未知时显式为空，不伪造时间。
- `fetched_at`：平台抓取时间。
- `topic_tags`：主题标签。
- `source_tier`：来源等级或热点来源属性。

用户对同一条新闻有两个明确动作：

| 用户动作 | 系统行为 |
| --- | --- |
| 查看原文或点击标题 | 在新标签页打开 `url`；不调用 Agent，不抓取和缓存原文全文。 |
| AI 深度研判 | 新建新闻上下文会话，或在用户明确选择后复用已有新闻会话；会话强制由新闻 Agent 处理。 |

新闻 Agent 的初始输入只包含上述结构化元数据，不传递新闻正文。用户后续追问默认维持该新闻锚点与新闻 Agent，直到用户新建会话、明确切换分析对象或主动切换 Agent。

## 4. 严格锚定的新闻研判

新闻 Agent 可以联网检索，但联网的作用是验证与补充，不是替换用户选择的新闻主题。

每次研判都保留 `news_id` 和原始新闻元数据作为锚点；检索查询必须由新闻实体、事件、时间范围和用户问题组成。若用户问题已转向另一事件，Agent 必须提示“这属于关联话题，是否切换分析对象”，获得明确同意后才创建新的锚点。

### 默认输出结构

1. **原新闻解读**：明确说明原始摘要声称了什么，不能把摘要中的主张表述为已核验事实。
2. **交叉验证结论**：将关键主张标为“已证实”“存在冲突”或“暂无法确认”，并关联证据来源。
3. **时间线**：按时间列出已验证的前因、关键节点和最新进展。
4. **影响分析**：仅基于证实事实，按与事件相关的公众、行业、市场、政策或学术影响展开。
5. **观点与分歧**：清晰区分事实、合理推断和带立场的观点。
6. **不确定性与待核验线索**：说明信息缺口、来源冲突、时效风险，以及未审核来源提供的线索。
7. **引用来源证据卡片**：默认展示，供用户直接核验。

### 事实规则

- 任何关键事实必须至少有一个已启用来源支持；对高影响主张应优先寻找一级来源或两个独立来源交叉支持。
- 未审核来源可用于发现线索，但不能独立支撑事实结论，且不能进入正式证据卡片。
- 来源冲突时呈现冲突、来源与时间，不由模型无证据裁决。
- 无法验证时明确写“暂无法确认”；不得用推断填补事实缺口。
- Agent 不抓取、存储或复述受版权保护的完整新闻正文；只处理标题、来源、链接、摘要和联网检索返回的必要摘录/元数据。

## 5. 证据卡片

新闻 Agent 的每个关键结论附默认可见的证据卡片。卡片字段：

| 字段 | 说明 |
| --- | --- |
| `claim_id` | 关联的研判结论 ID |
| `relation` | `supports`、`contradicts` 或 `context` |
| `source_name` | 站点或机构名称 |
| `source_tier` | 一级、二级、三级或未审核线索 |
| `title` | 引用条目标题 |
| `published_at` | 原始发布时间 |
| `url` | 用户可访问的原始链接 |
| `excerpt` | 必要的短摘录或结构化事实，不复制全文 |
| `verification_status` | `verified`、`conflicted`、`unverified_lead` |

未审核线索不得进入默认正式证据卡片；若在“不确定性与待核验线索”中展示，必须使用醒目标识且不赋予来源等级。

## 6. 来源库与审核流程

来源库是后台维护的独立业务资源，不写死在代码中。第一版只有一个系统管理员账号；普通用户不能提交来源，也不能审核、启用、分级或拉黑来源。

### 来源记录

每个来源至少包含：

- 站点名称、主域名和允许子域名。
- 主体类型：政府/监管、国际组织、公司公告、学术出版/预印本、综合媒体、财经媒体、行业媒体、研究机构、大学/实验室、其他。
- 来源层级：一级、二级、三级、线索源或黑名单。
- 领域标签、地区、语言和抓取方式（RSS、官方 API、允许的搜索入口）。
- 状态：`pending`、`enabled`、`lead_only`、`rejected`、`blocked`、`needs_review`。
- AI 建议评分、评分理由、人工审核结论、审核理由、审核时间和审核人。
- 最近抓取状态、失败次数、最近复审时间和创建/更新时间。

### AI 候选评分

后端在新闻检索或热点抓取中发现新域名时，可创建候选来源。AI 只给出建议评分和理由，不自动将来源加入可信库。评分必须覆盖：

- 主体权威性与可识别性。
- 域名与品牌一致性、HTTPS、仿冒和钓鱼风险。
- 领域相关性与地域/语言覆盖。
- 已知编辑标准、原始来源能力和历史可靠性信号。
- 近期可访问性、重复转载比例与异常内容信号。

候选状态始终为 `pending`，不用于事实级检索或证据卡片。

### 管理员审核

唯一系统管理员在后台对候选来源执行四种结果：

| 决定 | 后果 |
| --- | --- |
| 启用 | 标记为 `enabled`，指定一级/二级/三级层级，可作为正式证据。 |
| 降级为线索源 | 标记为 `lead_only`，仅可辅助发现线索。 |
| 拒绝 | 标记为 `rejected`，不参与检索与证据。 |
| 拉黑 | 标记为 `blocked`，禁止抓取、检索与再次自动入池。 |

每次审核都写入审计事件，记录管理员、时间、前后状态、来源、AI 评分、人工理由和相关候选 ID。管理员的审核结果用于改进候选排序规则，但不得自动改变已审核来源状态。

已启用来源仍需定期复审。连续抓取失败、域名变更、仿冒信号、频繁更正或质量下降时，系统标为 `needs_review`；在复审前不再作为高置信事实的唯一依据。

## 7. 热点池与缓存

热点由后端定时抓取和缓存；新会话读取热点池，不在用户打开首页时直接访问外部站点。

### 刷新策略

- 已启用来源按来源配置的间隔增量抓取；默认增量刷新间隔为 15 分钟。
- 每 6 小时执行过期清理、跨来源去重和主题重聚类。
- 抓取结果规范化、去重、计算时效衰减、标注主题并写入热点池。
- 热点选择兼顾时效、来源层级、热度、主题多样性和重复度，不能只按单一平台热榜排序。
- 任一来源抓取失败时保留最后成功缓存，向运维记录降级状态；前端可显示抓取时间，但不得把缓存伪装为实时新闻。

### 数据边界

热点池只保存标题、来源、链接、摘要、发布时间、抓取时间、主题、热度、来源状态和内容指纹。内容指纹用于去重，不保存或重建新闻全文。

当前直接抓取热搜平台并写本地 JSON 缓存的实现，只能作为过渡能力；目标实现必须以来源库状态、抓取适配器、可审计任务记录和数据库热点池为准。

## 8. 旅行 Agent：行程规划与存档

旅行 Agent 是行程规划工具，不承担旅行全生命周期服务。它负责需求收集、地点/天气/路线等规划信息查询、当前草稿生成与调整、用户确认和行程存档。

### 行程状态

```text
需求收集 -> 当前草稿 -> 调整 -> 确认 -> 不可覆盖的行程存档
```

- 草稿只保留一份当前方案，不生成多方案对比。
- 用户可以通过对话或界面手动编辑草稿中的景点、时间段、地点和备注。
- 手动编辑后，草稿标记为“已手动调整”；旅行 Agent 后续修改必须以当前草稿为输入，不能重新生成整份方案覆盖用户编辑。
- 用户点击“确认行程”时才创建存档。生成和修改草稿不自动产生版本。
- 用户从存档继续编辑时，系统创建新的当前草稿；下一次确认产生新的存档，旧存档保持不变。
- 路线、天气、地点等外部信息在生成后冻结。只有用户主动点击“更新信息”才重新查询；更新先显示差异和更新时间，可能覆盖手工编辑时必须由用户选择应用。

旅行 Agent 不包含相册、EXIF、照片地图、AI 游记、打卡、实际花费记账、费用统计、订票、订酒店、支付或订单承诺。它可以提供规划建议和外部搜索入口，但不形成预订交易流程。

## 9. 学术 Agent：科研检索与写作

学术 Agent 保留为科研检索与写作助手，支持：论文检索、摘要阅读、引用关系、研究方向分析、文献综述、研究空白/创新点梳理、论文润色、结构建议、摘要改写、翻译、引用格式化、BibTeX/GB-T 7714/APA/IEEE 转换、Cover Letter 和审稿回复辅助。

事实检索只允许 arXiv 和已接入的论文数据库；禁止使用通用网页搜索补充会议、期刊、机构或其他外部事实。无法由论文数据库可靠支持的内容，Agent 必须说明能力边界，不能推测或编造。

论文草稿、段落、投稿材料和用户上传文本只作为当前会话的临时上下文：不写入长期记忆、用户画像或可复用知识库。会话结束或按会话保留策略到期后，原始文本必须清除。用户主动收藏的论文条目和确认的引用清单可作为独立的结构化数据保存，但不保存原始草稿。

同一学术会话允许切换研究主题。切换时创建新的研究上下文分段，后续检索和分析默认不携带上一个主题的论文、结论和引用，除非用户明确要求复用。

写作类输出必须标注为基于用户提供文本或已检索论文的辅助结果；不得虚构论文、引用、实验结果、作者信息、期刊指标或录取率。

## 10. 权限、审计与失败行为

- 新闻阅读链接公开跳转到外部站点；平台不代理原文正文。
- 新闻深度研判需要登录，分析会话和用户收藏只能由所有者访问。
- 仅系统管理员可访问来源库后台、审核队列和来源级别变更记录。
- 抓取、候选创建、AI 评分、管理员审核、来源状态变化和热点发布均产生结构化审计事件。
- 新闻 Agent 只能调用新闻检索、来源库查询和允许的交叉验证工具；不能继承旅行、文件、Shell 或任意 MCP 工具权限。
- 旅行 Agent 只能调用规划所需的地点、天气、路线和允许的旅行搜索工具；不获得文件、支付、Shell 或新闻来源库审核权限。
- 学术 Agent 只能调用 arXiv 和论文数据库工具；不获得通用网页搜索、旅行、文件、Shell 或来源库审核权限。
- 联网检索失败时，Agent 仍可基于锚点摘要进行“未联网核验”的解释，并明确说明没有完成交叉验证；不得编造来源或证据卡片。

## 11. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 用户点击热点标题 | 外部链接新标签打开；不创建 Agent 会话。 |
| 用户点击 AI 深度研判 | 创建绑定 `news_id` 的会话，路由到新闻 Agent。 |
| 新闻 Agent 发现未审核域名 | 可作为待核验线索；自动进入 `pending` 审核池；不进入正式证据卡片。 |
| 已启用来源支持结论 | 结论附默认可见证据卡片，显示来源、时间、链接和关系。 |
| 两个来源冲突 | 输出同时展示冲突与不确定性，不强制下结论。 |
| 管理员将来源拉黑 | 后续抓取和检索过滤该域名，不能再次自动进入候选池。 |
| 普通用户访问来源库后台 | 返回拒绝访问，不泄漏审核数据。 |
| 缓存刷新失败 | 首页显示最后成功热点和抓取时间，后台记录失败；不发起用户请求内抓取。 |
| 用户从新闻问题切换到不相关事件 | Agent 请求确认切换分析对象，而不是静默偏移。 |
| 默认云合会话询问简单计算 | 云合直接回答，不委派。 |
| 默认云合会话询问论文检索 | 云合仅委派学术 Agent 处理该轮；下一条简单问题由云合接回。 |
| 用户手动选择旅行 Agent | 会话锁定到旅行 Agent，直到用户明确切回云合或新建会话。 |
| 用户手工改动旅行草稿 | 后续 Agent 修改以该草稿为基线，不能覆盖手工编辑。 |
| 用户确认旅行草稿 | 创建不可覆盖的存档；未确认草稿不创建历史版本。 |
| 用户未点击更新信息 | 草稿中的天气、路线和地点信息不自动刷新。 |
| 学术 Agent 用户粘贴草稿 | 原文仅用于当前会话，不进入长期记忆。 |
| 学术会话切换主题 | 新主题检索不默认引用旧主题的论文与结论。 |

## 12. 删除、收缩与重构清单

| 当前能力 | 决定 | 原因 |
| --- | --- | --- |
| 情感识别 | 删除 | 未确认用户价值，增加模型调用、数据处理和调度复杂度。 |
| 行程多方案生成与比较 | 删除 | 产品收敛为单草稿、确认存档；比较不再构成核心闭环。 |
| 相册、照片地图、AI 游记 | 从旅行 Agent 删除 | 不属于行程规划工具，且带来文件、EXIF、授权和隐私风险。 |
| 打卡、实际花费、费用统计 | 删除 | 不属于第一版行程规划闭环。 |
| 订票、酒店、支付/订单流程 | 删除或降级为外部入口 | 不建立交易承诺和订单责任。 |
| 旅行长期记忆 | 从旅行 Agent 移除 | 当前行程草稿/存档已满足业务；避免跨会话个人数据复杂度。 |
| 学术通用网页搜索 | 删除 | 学术事实边界收敛到 arXiv/论文数据库。 |
| 新闻热点本地 JSON 缓存 | 替换 | 改为来源库驱动、可审核和可审计的热点池。 |

## 13. 与重构的关系
